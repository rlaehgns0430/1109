이번 실험에서는 퀵 정렬에서 피벗을 어떻게 고르냐에 따라 성능이 어떻게 변하는지 확인해 보았습니다. 
데이터를 1000개부터 20000개까지 늘려가며 테스트해 보니, 세 가지 방법 모두 데이터가 늘어나는 양에 비례해서 비교 횟수가 안정적으로 증가하는 것을 볼 수 있었습니다. 

세 방법 중에서 성능을 비교해 보면 세 원소의 중앙값을 선택하는 방식이 가장 비교 횟수가 적어 효율적이었습니다. 
첫 번째 원소만 고르는 방식은 데이터가 불균형하게 나뉠 확률이 높아서 비교를 가장 많이 해야 했습니다. 반면 중앙값 방식은 처음, 중간, 끝 값 중 딱 중간 요소를 찾아서 기준(피벗)으로 삼기 때문에, 
데이터를 최대한 반반씩 예쁘게 쪼개주어 정렬 속도가 가장 빨라지는 원리였습니다. 
무작위 방식도 최악의 경우를 피해 가기 때문에 중앙값 방식만큼은 아니지만 꽤 괜찮은 성능을 보여주었습니다.

보너스로 진행한 재귀 방식과 반복문(스택) 방식의 실행 시간 비교에서는 반복문을 쓴 퀵 정렬이 더 빠르게 나왔습니다. 
재귀 함수는 컴퓨터가 계속 똑같은 함수를 새로 호출하고 실행하느라 시스템적으로 리소스를 많이 잡아먹는 오버헤드가 발생하는 반면, 
반복문 방식은 배열로 만든 스택을 직접 컨트롤하면서 루프를 돌기 때문에 군더더기 없이 속도가 더 빠를 수밖에 없다는 것을 실험 결과를 통해 확인할 수 있었습니다.
